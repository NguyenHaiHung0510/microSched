# 088 — One-shot day reminders and useful notification content

Status: Owner-approved implementation; independent QA and production delivery pending.

Day annotations gain a one-shot reminder through the existing Task reminder editor: absolute datetime or a before/after offset from the start date with an explicit Vietnam anchor clock. The compact **Nhắc tôi** action sits beside edit/delete (design A). Annual recurrence is deferred. Start-date edits reschedule pending relative reminders; end-date edits and absolute reminders retain their existing instant. Deletion cascades owned reminders. Existing revision, sending, visibility, late-window and retry contracts remain.

Public notification sources include their meaningful source fields: tracker label/custom reminder and actual after-entry age; subscription expiry/amount/period/note; Task detail/deadline/checklist; event time/location/description; day label/date-range/note. One-shot tracker copy uses its configured reminder, not arbitrary historical entries. Private sources use abstract content before public text is loaded for push. Grouped tracker notifications retain **Hi, it's microSched 🌸**, list public details and one generic private line when mixed, with no extra push fanout. Mimi removes arbitrary80/240 copy caps but retains STANDARD/nonprivate eligibility and device opt-in. The generic service-worker fallback stays generic.

Payload serialization fits a3500-byte UTF-8 JSON budget, retaining routing and app originals; necessary shortening ends visibly with an invitation to open the app. OS banner expansion is device-controlled. Notification links resolve the selected reminder to its currently visible source; a private/inaccessible source remains gated.

Recurring grouped/individual tracker and subscription fanout rechecks current public visibility before each device handoff. Newly private or unavailable sources use abstract copy, while mixed groups retain the other public details and one generic private line. These reads finish before provider I/O; already handed-off notifications cannot be recalled. Regression coverage changes privacy in a separate transaction during the first device send and checks the second payload, unchanged fanout/accounting and transaction release. Task collection recovery reads only its owned reminder snapshot fields, retaining historical0017 evidence without depending on the new annotation column.

Migration0018 is additive on upgrade: annotation FK, four-source CHECK, active-source uniqueness and start-date trigger. No automatic deploy migration, no production downgrade or Neon branch administration. Apply only under the scoped Owner production-migration grant with backup, local rehearsal, schema/drift evidence and compatible rollback. DDL rollback refuses nonempty annotation reminders; application rollback must retain schema compatibility.

Acceptance: focused domain/real-PG lifecycle, private/no-ciphertext guards and send revalidation, delivery fanout/TTL regressions, Unicode transport budget, desktop/touch browser entry/edit/deep-link cases, full required CI gates and independent reconciled QA.
