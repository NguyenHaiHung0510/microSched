# Decision-model landscape addendum — 2026-09-30

Status: read-only market/source research for Owner decision. No key, inference, benchmark, dependency install, route change or product implementation. This updates the dated candidate inventory in `07-model-landscape-luna.md`; it does not supersede Mimi's authority, privacy or confirmation contracts.

## New primary-source observations

- **Kev** is an Apache-2.0, open-weight Jev-like family (0.8B, 4B, 9B and 27B) with Choice/Score/Noul-style decisions. Its maintainer says the API matches TypeSafe's `/v1/systemone` contract and publishes model cards and evaluation code. The maintainer's cross-model accuracy numbers are *not* a controlled Mimi/Vietnamese benchmark; the README explicitly notes Jev was run only on development sets in its comparison. Hosting Kev locally would add GPU/runtime responsibility, so it is not free operationally. [Maintainer repository](https://github.com/jaredpalmer/kev).
- OpenRouter now lists **Kev 4B** via SiliconFlow as a hosted decision route, with an 8K context and a displayed $0.042/M input price; provider uptime/availability and pricing are rolling catalog observations, not SLA or Mimi quality proof. Its model page says it uses the same decision-shaped API. [Kev 4B listing](https://openrouter.ai/jaredpalmer/kev-4b).
- OpenRouter lists **Jev Router** (released 2026-09-25) as a separate route that chooses a *generative* model and reasoning effort. It is not interchangeable with Jev 1.13's typed Decision API. The catalog currently displays zero router token price, but downstream chosen-model cost, route transparency, privacy, tool/effort fidelity and fallback behavior need exact verification before treating it as cheaper or compatible. [Jev Router listing](https://openrouter.ai/typesafe/jev-router).
- TypeSafe's official documentation continues to define Jev/System One as constrained decisions with probabilities, not prose or an agent loop; calibration is aggregate and cannot make one decision safe by itself. [TypeSafe System One](https://docs.typesafe.ai/concepts/system-one).

## Revised recommendation

Do not make Jev the architecture or add a decision call to every Mimi turn. If triage becomes a measured need, compare (1) deterministic rules with no extra call, (2) a typed decision in the existing generative turn, (3) Jev 1.13, and (4) hosted Kev 4B on the same held-out Vietnamese Mimi cases. Compare downstream cost per correctly completed task, false-create/false-approval risk, abstention/calibration, latency and exact privacy route; a single-call price ranking is insufficient. Keep both specialist models optional behind a vendor-neutral typed-decision interface. Jev Router is a *separate model-routing hypothesis* whose hidden route/effort selection may conflict with exact-provider and reproducible-eval requirements; do not place it in the D10 control lane.

Before changing any runtime, the nearer product gate remains a no-key synthetic transport parity/recovery check against the existing adapter, followed by truthful progress/feedback and the already-defined live-eval approval gate. A full runner/framework replacement needs a scenario-parity prototype with measured maintenance/recovery gain, not popularity or demo claims. This is advice, not implementation or paid-eval approval.
