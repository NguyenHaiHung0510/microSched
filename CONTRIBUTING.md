# Contributing

English | [Tiếng Việt](CONTRIBUTING.vi.md)

microSched is a personal project, but feedback and clearly scoped pull requests are welcome.

## Before you start

- For major changes to the product, architecture, or data model, open an issue/discussion to agree on a direction first.
- Read `AGENTS.md`, the relevant decision brief, and `docs/harness-policy.md` for workflow/authority. `CLAUDE.md` is a compatibility pointer only.
- Do not include secrets, credentials, tokens, real personal data, or production payloads in code, fixtures, logs, issues, or PRs.

## Pull requests

- Create a separate branch and open a PR against `develop`; do not push directly to `main` or `develop`.
- Describe the goal, scope, trade-offs, and checks you have run; clearly distinguish what has not been verified.
- Run the relevant commands in the backend/frontend READMEs before opening a PR.
- Keep PRs small and leave out unrelated refactoring. Merging and deployment are subject to owner/repository gates.
